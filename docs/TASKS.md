# «Давление» — задачи (этапы 1–3)

Правила процесса: ветка от `develop`, одна задача = один PR, мержит владелец. Логика (`addons/master_core`, `game/logic`) не зависит от сцен и узлов (только `RefCounted`) и тестируется headless.
Команда тестов везде одна: `godot --headless -s tests/run_all.gd` (код выхода ≠ 0 при падении).

## Структура проекта

```
master-pressure/
  project.godot                 # рендер gl_compatibility (веб + слабые Android)
  addons/master_core/           # ядро серии, ничего не знает о трубах
    grid/        grid.gd, dir.gd
    rng/         seeded_rng.gd          # свой PCG32: одинаковый результат везде
    search/      search_stats.gd, bnb.gd # каркас перебора с отсечениями
    level/       level_io.gd, pack_io.gd, daily.gd
    undo/        undo_stack.gd
    share/       share_text.gd
  game/
    logic/       pieces.gd, pressure_level.gd, pressure_eval.gd,
                 pressure_solver.gd, pressure_generator.gd, difficulty.gd
    ui/          main.tscn, board_view.gd, hud.gd
  tools/         gen_levels.gd, agent_player.gd, report.gd, setup_godot.sh
  tests/         run_all.gd, test_*.gd, fixtures/*.json
  levels/        packs/*.json
  docs/          GAME_DESIGN.md, TASKS.md, reports/
  .github/workflows/  tests.yml, web.yml
```

## Этап 2. Генератор, решатель, сложность (headless)

### T-02. Каркас репозитория и тестов
**Что сделать:** структура выше; `.gitignore` для Godot; минимальный тест-раннер без плагинов (находит `tests/test_*.gd`, вызывает методы `test_*`, печатает итог); `tools/setup_godot.sh` скачивает Godot 4.7.2 для headless; workflow `tests.yml` гоняет тесты на каждый PR.
**Готово, когда:** на PR в `develop` CI зелёный с одним тестом-пустышкой, и красный, если тест специально сломать.

### T-03. Модель уровня и формат JSON
**Что сделать:** типы клеток и участков, маски концов, поворот; уровень (размер, клетки, источник и его выходы, краны и требования, `H`, `L`, seed); сериализация.
**Готово, когда:** три примера из GAME_DESIGN.md лежат в `tests/fixtures/` и проходят цикл «загрузить → сохранить → загрузить» без потерь; поворот 4 раза возвращает исходную маску для всех типов.

### T-04. Оценщик напора
**Что сделать:** `pressure_eval.gd` по разделу 3 GAME_DESIGN: мокрая сеть, протечки, Дейкстра по (клетка, сторона входа), напор на кранах, победа.
**Готово, когда:** на решениях трёх примеров числа совпадают с документом (8→3; 2/2; 4/2 при 1 протечке), на ловушках тоже (1; A=1/B=4; A=5/B=1); совпадение с эталонными значениями на ≥ 200 уровнях из fixtures (эталон дадим отдельным файлом).

### T-05. Сидовый ГСЧ
**Что сделать:** свой PCG32 в `master_core/rng` (не `RandomNumberGenerator`: его поведение между версиями движка не гарантировано — не подтверждено).
**Готово, когда:** для 3 фиксированных seed первые 1000 чисел совпадают с зафиксированным файлом.

### T-06. Точный решатель
**Что сделать:** перебор мокрых сетей («соединить / протечь» для каждого конца) + отсечение по верхней оценке напора; результат: оптимум по каждому крану, число побеждающих сетей (до лимита k), статистика (узлы, отсечения, время); лимит времени с флагом «не досчитан».
**Готово, когда:** на примерах: 35/1, 162/1, 144/2 (соединяющие / побеждающие); на 100 случайных уровнях 4×4 совпадает с полным перебором поворотов; замер времени на 5×5, 6×8, 7×9 записан в PR.

### T-07. Генератор
**Что сделать:** «построить сеть → заполнить → решатель → требования = оптимум − запас → фильтр интересности → перемешать» (раздел 6). Параметры: размер, краны, доля Y/X, запас, L.
**Готово, когда:** по 100 уровней на размеры 5×5, 6×7, 7×9: каждый проверен решателем, старт не решён, уровень с тем же seed генерируется побайтно одинаково.

### T-08. Оценка сложности v0
**Что сделать:** признаки из раздела 5 + итоговая оценка; сохранять их в JSON уровня.
**Готово, когда:** для каждого уровня из T-07 есть признаки и оценка; на трёх примерах оценка растёт в порядке 1 < 2 ≤ 3 (иначе объяснение в PR).

### T-09. Агент-игрок и отчёт
**Что сделать:** `agent_player.gd`: (1) повторная проверка решаемости решателем, (2) «человекоподобный» бот (локальный поиск без знания решения): ходы, провалы. `report.gd`: Markdown + CSV + гистограмма в `docs/reports/`.
**Готово, когда:** сгенерировано 1000 уровней, **все решаемы** (0 провалов повторной проверки), в отчёте видно распределение сложности по размерам и связь «оценка ↔ ходы бота»; отчёт смержен.

## Этап 3. Играбельный прототип (без красивой графики)

### T-10. Поле и поворот касанием
**Что сделать:** отрисовка примитивами (линии, цвета), касание = поворот на 90°, цели ≥ 48 dp, только вертикальная ориентация, раскладка по решению из T-01 (нижние 2/3 или тачпад).
**Готово, когда:** на телефоне через веб-сборку уровень 7×9 играется одним большим пальцем; промахов по соседним клеткам нет за 20 касаний подряд (проверяешь ты).

### T-11. Живой напор и победа
**Что сделать:** пересчёт после каждого хода, «есть / нужно» на кранах, яркость воды, отметки протечек, экран «решено» → следующий уровень.
**Готово, когда:** три примера из документа показывают на экране ровно те числа, что в документе; победа срабатывает сразу после последнего нужного поворота.

### T-12. Пак уровней для прототипа
**Что сделать:** 30 уровней из генератора по росту сложности (5×5 → 7×9), включая 2–3 «сюрприза» с выгодной протечкой. Отладочная строка: seed и оценка сложности.
**Готово, когда:** пак лежит в `levels/packs/proto.json`, играется по порядку, прогресс сохраняется между запусками.

### T-13. Веб-сборка на GitHub Pages
**Что сделать:** экспорт Web **без потоков** (`thread_support=false`: GitHub Pages не отдаёт заголовки COOP/COEP); workflow `web.yml` собирает и публикует при мерже в `develop`.
**Готово, когда:** ссылка открывается на твоём телефоне, пак из T-12 играется; размер загрузки указан в PR (wasm пустого проекта ≈ 40 МБ, проверено).

## Подготовка к Google Play

### T-25 Иконка, заставка, «Как играть» — в работе
- Иконки рисует код: `godot --headless -s tools/make_icons.gd` → `assets/icons/` (192, адаптивная 432 фон/передний план, 512 для магазина, заставка).
- Иконка проекта, заставка и иконки лаунчера в `project.godot` / `export_presets.cfg`.
- Экран «Как играть»: пять правил с картинками. При первом запуске он открывается сам, «Понятно» сразу запускает игру. Повторно открывается из настроек.
- Готово, когда: на телефоне своя иконка (и круглая, и квадратная маска), при первом запуске виден «Как играть», тесты зелёные.

### T-26 Релизная AAB-сборка — далее
- Gradle-сборка (шаблон в `android/build`), формат AAB, targetSdk 36, arm64 + armv7.
- Подпись ключом загрузки из секретов GitHub (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`). Ключ в репозитории не хранится.
- Версия: versionCode из номера сборки, versionName из тега.
- Готово, когда: workflow выдаёт подписанный `.aab`, и Play Console принимает его во внутренний тест.

### T-27 Материалы для магазина — далее
- Баннер 1024×500, 4–8 скриншотов телефона, краткое (до 80 символов) и полное описание, политика конфиденциальности (страница в репозитории), ответы для Data safety (данные не собираются) и анкеты рейтинга.
- Готово, когда: всё лежит в `store/` и закрывает все обязательные поля страницы приложения.
